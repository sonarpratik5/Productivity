Productivity development context
Updated: 2026-08-10

Product intent
- Native macOS, privacy-first personal productivity tracker.
- Flagship concept is multistream activity tracking: the app should preserve simultaneous streams of activity instead of flattening the day into one app-at-a-time timeline. Example: coding in Xcode while Spotify or Safari audio is active, or multiple meaningful visible windows are part of the work context.
- Data should stay local. The app currently uses file-backed local storage under Application Support, plus UserDefaults for some preferences/manual event metadata.

Important architecture
- App/AppEnvironment.swift wires dependencies: MacOSActivityTracker, InsightEngine, FileBackedActivityRepository, AppSettings, PomodoroViewModel. It also records lifecycle segments for app open/close and system sleep/wake.
- Core/Models/ActivitySegment.swift is the central normalized data model. Every tracked stream becomes an ActivitySegment with app, bundle id, title, optional userDescription, date interval, category, and productivityScore.
- Core/Services/ActivityTracking/MacOSActivityTracker.swift is the live macOS tracker. It tracks:
  - primary/frontmost app sessions,
  - background companion sessions, mainly active audio apps where available on macOS 15+ with fallback allowlisted media apps,
  - visible companion sessions for recently active meaningful windows that remain visible and above area thresholds,
  - lifecycle interruptions like sleep/session resign through AppEnvironment.
- Core/Persistence/ActivityRepository.swift stores segments locally. FileBackedActivityRepository upserts by UUID into daily binary property-list files and protects writes with a length-prefixed WAL file, then flushes dirty days on a 30 second debounce and lifecycle events.
- Core/Services/Classification/ActivityClassifier.swift maps apps/rules to ActivityCategory and productivityScore. Manual label rules can override defaults.
- Core/Services/Insights/InsightEngine.swift computes daily overview from primary/planned context-aware segments.

Multistream algorithm notes
- ActivitySegment marks companion streams by userDescription containing "Background companion activity" or "Visible companion activity".
- ActivitySegment.primaryAttentionSegments(from:) filters out companion and lifecycle streams, sorts by start time, resolves same-start conflicts by productivityScore, and trims each primary segment to end at the next primary start.
- TimelineStream.packed(from:) builds timeline lanes:
  - lane 1: normalized primary attention,
  - next lane: lifecycle segments,
  - additional lanes: companion segments after coalescing by bundle id, subtracting overlaps with the same app already represented as primary, and packing non-overlapping segments into compact lanes.
- TimelineLabelSegment.derived(from:) turns primary + companion context into productive/unproductive/unknown label intervals. If only companion streams are active, it currently marks that interval unproductive; when primary streams exist, dominant label is derived from primary segments.
- InsightEngine.dailyOverview intentionally uses primary/planned context-aware time rather than counting all companion streams, avoiding double-counting simultaneous activities.

Dashboard and insights flow
- DashboardViewModel receives live snapshots from ActivityTracking.activitySegments, filters deleted IDs, refreshes views, then persists live segments.
- It merges persisted + live segments by UUID, keeping the latest endDate.
- ManualActivityEvent creates synthetic ActivitySegment values with bundle id prefix manual.event.; these can override tracked time in InsightEngine by subtracting planned intervals from tracked segments.
- WeeklyInsightsView currently takes weekSegments and labelSegments, derives label segments when needed, supports week/month/year periods, clamps to the selected period, and shows breakdown, history, and InsightStripView summaries.

Working rules for future changes
- Keep changes scoped to the requested feature/refinement.
- Preserve local-first storage unless explicitly changing persistence strategy.
- Do not collapse multistream data into one stream for UI or insights unless the specific metric requires primary-attention-only time.
- When changing insights, decide explicitly whether the metric should use primary attention only, companion streams, lifecycle streams, manual planned events, or a derived label timeline.
- Use SwiftUI/Observation patterns already present. Avoid Combine.
- Validate Swift changes with Xcode diagnostics or BuildProject when feasible.
